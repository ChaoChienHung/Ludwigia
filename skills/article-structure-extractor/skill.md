# Article Structure Extractor

目標：當使用者提供一篇「覺得寫得很好」的文章時，幫他逆向整理出文章骨架、每一節的目的、每節細項、轉場方式，以及一份可重用的模板，方便沉澱到 `docs/author/writing-notes.md` 或直接在之後套用。

## 何時使用

- 使用者說「幫我分析這篇文章怎麼寫的」
- 使用者想知道一篇優秀文章的結構、每節在做什麼、為什麼讀起來順
- 使用者想把某篇文章拆成可重用模板，而不是只做摘要

## 輸入

- 一篇文章內容（全文、節錄、Markdown、HTML、網址擷取結果皆可）
- 可選：文章類型（教學 / 觀點 / 比較 / paper note / 系統設計 / case study）
- 可選：希望輸出的粒度（只要大綱 / 要每節細項 / 要轉場分析）

## 輸出

- 一份結構化分析，至少包含：
  - 文章定位
  - 總體骨架
  - 每一節目的
  - 每一節細項
  - 轉場與節奏
  - 可重用模板
- 若適合，也可順手補進 `docs/author/writing-notes.md`

## 標準輸出格式

### 1) 文章定位

- 這篇文章主要屬於哪一類：觀點論述、教學拆解、比較分析、研究摘要、反思札記、case study、或知識型文章 / 方法筆記
- 目標讀者是誰
- 作者想讓讀者讀完後得到什麼

### 2) 總體骨架

- 用 5-8 個 section 概括整體順序
- 若有明顯的 opener / comparison / conclusion，也要標出

### 3) 每一節的目的與細項

對每一節至少回答：

- 這一節在完成什麼任務？
- 這一節裡面有哪些固定細項？
- 這一節是提供背景、定義、方法、限制、比較，還是收束結論？

### 4) 轉場與節奏

- 作者是怎麼把上一節自然帶到下一節？
- 是先給結論再展開，還是先鋪背景再亮答案？
- 讀者在哪些地方會感到「被穩定地帶著走」？

### 5) 可重用模板

最後輸出一份可以重複使用的模板，例如：

```text
1. Introduction: Why?
2. Introduction: What?
3. Approach: How?
4. Limitation
5. Comparison (Optional)
6. Conclusion: Key Takeaways
```

並補一句：

- 這套模板適合什麼主題
- 什麼情況下可以刪某一節
- 常見失敗是什麼

## 守則

- 不要把「摘要」誤當成「結構分析」
- 不只列標題，還要說明每一節的功能
- 若文章有明顯 writer-specific 材料，要區分哪些是可複用骨架、哪些只是作者個人素材
- 若這篇文章值得沉澱成長期模板，優先建議補進 `docs/author/writing-notes.md`

## 例子

### 使用者請求

```text
幫我分析這篇文章的結構，整理出它為什麼寫得順。
```

### 理想輸出

- `文章定位`
- `總體骨架`
- `每一節功能`
- `轉場方式`
- `可重用模板`

## 與其它技能的關係

- 如果目標是「把既有結構與素材轉寫成文章」，請改用 `article-structure-writer`
- 如果目標是「把分析結果沉澱成模板庫」，可在結束時建議更新 `docs/author/writing-notes.md`
