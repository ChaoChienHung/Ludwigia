# Article Structure Writer

目標：當使用者提供「文章結構 + 每節細項 + 原始素材」時，幫他把這些內容轉寫成一篇真正可讀的文章，而不是只保留條列式筆記。

## 何時使用

- 使用者已經有一個明確的文章骨架，想把它寫成完整文章
- 使用者手上有 bullets / notes / 方法比較 / paper takeaways，想轉成知識型文章
- 使用者說「請根據這個結構幫我寫成文章」

## 輸入

- 文章結構（例如 `Why -> What -> How -> Limitation -> Comparison -> Key Takeaways`）
- 每一節的細項
- 原始素材（筆記、段落、條列、英文草稿、中文草稿皆可）
- 可選：語氣（個人網站 / 教學文 / 正式 / 口語 / essay / 技術筆記）
- 可選：輸出目標（只要文字 / 要轉成 Ludwigia pseudo-markdown）

## 輸出

- 一篇完整文章草稿
- 若使用者明確要求，也可直接輸出成：
  - `notes/<slug>/<slug>.md`
  - `writing/<slug>/<slug>.md`
- 若已經在 Ludwigia repo 內工作，可順手用 `tools/create_content.py` 重生 `.html`

## 工作流程

### 1) 先確認文章任務

至少先釐清：

- 這篇文章是要教什麼、說服什麼，還是整理什麼？
- 目標讀者是誰？
- 結構是固定模板，還是可以微調？

### 2) 把條列素材映射到章節

對每一節回答：

- 哪些內容是背景？
- 哪些是定義？
- 哪些是方法本體？
- 哪些是限制、比較、或收束？

若素材順序混亂，要先重排，不要直接照貼。

### 3) 寫成「節與節之間會流動」的文章

轉寫時要注意：

- 不要把每節寫成互相斷裂的 bullet dump
- 需要自然轉場，讓讀者知道為什麼現在要進入下一節
- 保留結構感，但段落之間要有 narrative flow

### 4) 保留結構，不保留條列腔

目標不是把 bullet 變長，而是把它們變成：

- 有主語與重點的段落
- 有呼應上下文的節奏
- 可讀性高的知識型文章

### 5) 視情況加上強化元素

若主題適合，可加入：

- 小結（mini-summary）
- `<block>` 做 quick insight / quick notes
- 比較表或比較清單
- `Key Takeaways`

## 風格原則

- 優先保留使用者原本想法，不要過度替作者發明觀點
- 語氣要與文章目的相符：教學文就清楚、essay 就有節奏、技術文就準確
- 若使用者要的是「知識型文章」，應優先讓文章結構清楚，而不是追求花俏句型

## 建議輸出格式

### A. 只要文章草稿

- 直接輸出完整文章

### B. 要 Ludwigia pseudo-markdown

- 補 `<meta>`
- 用 `# Title`、`## Section`、必要時加 `<block>`
- 需要時用 `tools/create_content.py --source ... --force` 重生 `.html`

## 常見失敗

- 只是把 bullet 串成長句，沒有真正整理結構
- 每節都像摘要，缺少主次關係
- `Comparison` 與 `Limitation` 寫得太晚，讓文章前半像單向介紹
- 只顧語句漂亮，忽略 technical correctness

## 例子

### 使用者請求

```text
請根據這個結構和底下素材，幫我寫成一篇知識型文章。
```

### 理想輸出

- 一篇完整文章
- 若在 Ludwigia 內，可再輸出成 `notes/**.md` 或 `writing/**.md`

## 與其它技能的關係

- 如果目標是「從好文章反推結構模板」，請改用 `article-structure-extractor`
- 如果目標是「已經有結構與素材，要轉成文章」，才用本技能
