# Portals & World Performance

這份文件記錄 2026-11-15 對 Aetheria Portals（`portals/`）與 Ludwigia World（`portals/realms/world/`）做的效能優化：問題在哪裡、改了什麼、怎麼量測，以及之後要避免哪些寫法。對應的 commit 是 `c50a0c9`（效能與互動）和 `fcd802a`（手機瀏覽、i18n、視覺精修）。

核心原則只有一條：**每一幀的成本應該取決於畫面上看得到什麼，而不是世界有多大。**

## 量測方式

- 工具：headless Chrome（桌面 1440×900；模擬手機 390×844，CPU 降速 4 倍），再加上 Node 微基準，對深度排序單獨計時。
- headless Chrome 在優化前就能維持 60 fps，所以 fps 看不出差異。真正有意義的指標是主執行緒忙碌比例、每幀 JS 時間、每秒強制排版（forced layout）次數，以及 compositor 圖層面積。
- 尚未驗證：真實手機上的體感。

## 優化前後

## World（原生 Canvas 等軸測引擎）

### 1. 深度排序：從兩兩比較改成掃描線

- **問題**：等軸測畫面必須決定物件的繪製先後。原本每兩個物件都比一次（O(n²)），世界越大越慢；2,296 個物件時單次排序就要 101 ms。
- **做法**：依螢幕欄位做掃描（screen-column sweep），只比較在螢幕上可能互相遮擋的物件，再用 binary heap 做拓撲排序。
- **不退化**：`isBehind` 的前後判斷規則與閉環修復邏輯完全沒動，`AGENTS.md` 的「拓撲深度排序無閉環契約」仍然成立。

### 2. 只畫看得到的東西

- 地形圖塊、地面裝飾、浮島邊緣與雲、粒子：依視口範圍裁剪（viewport culling）。
- 靜態建築與家具：依佔地範圍（footprint）裁剪。

### 3. 地形只分類一次，並批次繪製

- 地形類型在載入時算一次，存進 typed array，不再每幀重新判斷。
- 每幀只處理可見的圖塊，並依「透明度 × 顏色」分組批次填色，減少 Canvas 2D 的狀態切換與 draw call。

### 4. DOM 與 CSS 變數只在改變時寫入

- 原本每幀都寫 DOM 或 CSS 變數，造成手機上每秒 59 次強制排版；改成值有變才寫，降到 0 次。

### 5. 依情境降低渲染成本

- **解析度倍率上限**：桌面 2 倍、觸控裝置 1.75 倍。高解析手機的像素數量差距很大。
- **被模糊面板蓋住時降到約 20 fps**：面板後方本來就看不清楚。
- **手機不使用 HUD 的即時背景模糊**：`backdrop-filter` 疊在每幀更新的 canvas 上，成本很高。
- **支援 `prefers-reduced-motion`**。

## Portals 大廳（React + Vite）

### 1. 動畫只在需要時才跑

- 鏡頭的彈簧動畫 `requestAnimationFrame` 只在鏡頭移動時執行，停下來就結束迴圈。
- 畫面外的傳送門暫停動畫。
- 日夜圖層只保留目前和正在淡出的兩層，其餘不掛載。

### 2. 減少重新渲染與昂貴的繪製

- 傳送門元件做 memo，避免一個狀態改變就讓整排傳送門重新渲染。
- 移除光帶（ley line）上的 SVG blur 濾鏡。
- 進度條改用 `transform: scaleX`，交給 compositor 處理，不觸發排版。
- 這些改動讓 compositor 圖層面積從 57.7 MP 降到 20.9 MP，估計的手機 GPU 記憶體從約 1.6 GB 降到約 590 MB。

### 3. 互動流程與視覺（`fcd802a`）

- 點門直接傳送（約 0.7 秒漩渦轉場，Esc 可取消），刪除原本的 `WorldPreviewModal` 介紹面板；hover 時界標卡可選擇性顯示縮圖（有圖才顯示）。
- 歡迎導覽只在第一次造訪時出現。沒有目的地的門保留為「封印中」的暗色佔位。
- 手機（< 768px）改成一次停在一座門的滑動瀏覽，底部卡片附「進入」按鈕，滑動不會被誤判為點擊。
- 所有文案集中在 `portals/src/i18n.ts`（三種語言），跟隨主站的 `site_lang_v1`。
- 視覺收斂：accent 只用全站 palette 投影的單一色；中性色表面；一套 chip／panel／button 規則；字級固定 4 級；Cinzel 只用於品牌與大標。移除閃爍 sparkle、旋轉太陽光環、第二顆月亮與多色光帶；日夜自動循環預設關閉。

## 之後的守則

新增功能時，以下寫法會讓效能回到原點，應該避免：

- 在每幀的迴圈裡做「全部物件兩兩比較」或「掃過整張地圖」的工作。新的大型物件也要能被 culling。
- 每幀無條件寫 DOM、CSS 變數或 React state。
- 在每幀更新的 canvas 上疊 `backdrop-filter` 或 SVG 濾鏡，特別是手機。
- 常駐、不會停止的 `requestAnimationFrame` 迴圈。
- 一次掛載所有日夜或天氣圖層，而不是只掛需要的那幾層。
