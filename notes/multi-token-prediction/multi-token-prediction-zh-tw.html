大語言模型能接續一段文字、完成一段程式，背後常有一個共同的訓練任務：根據已經出現的 token，預測下一個。這就是 Next-Token Prediction（NTP，下一個 token 預測）。它看起來簡單，卻能讓模型從大量文字與程式中反覆練習如何接續前文。

NTP 的力量，以及它留下的兩個問題

假設一段文字被切成 A B C D。以 NTP 訓練時，模型會看 A 預測 B、看 A B 預測 C，再看 A B C 預測 D。一段訓練序列的許多位置都能提供監督；任務也與自迴歸生成時「根據前文決定下一個 token」的形式相符。NTP 並非只讓整段文字產生一個答案，也不是無法學到長距離關係。

但仍有兩個值得追問的空間。第一，同一個位置的直接預測目標只有下一個 token：如果也要求模型預測更遠的未來，會不會提供有用的額外監督？ 第二，生成一段回答時，模型還不知道自己下一步會選什麼，必須先產生它，才能沿著這條路繼續寫；能不能減少反覆等待主模型的時間？第二個問題來自自迴歸解碼的序列依賴，不能簡單歸咎於 NTP 的訓練 loss。

訓練時，正確的 B C D 已經存在。模型可以一次讀入序列，透過 causal attention mask 讓每個位置只使用當前及之前的資訊，平行計算各位置的預測與 loss。生成時沒有未來的正確答案，要先選出 B，才能把它接回前文決定 C。訓練能平行計算許多位置，並不表示生成也能直接一次決定整段文字。

MTP：共同的問題，不同的實作

Multi-Token Prediction（MTP，多 token 預測）從第一個問題出發：在某個前文位置，除了下一個 token，也嘗試預測後面更多位置。它可以讓主模型接收額外的未來位置監督；如果這些預測還能便宜地提出合理候選，也可能服務第二個問題。不過，MTP 是一個方法家族，不是一套固定的 heads、loss 或解碼流程；兩種用途可以結合，也可以分開。Gloeckle et al., 2024；DeepSeek-V3, §2.2

沿用 A B C D 的例子：看見 A 後，除了預測 B，還可以增加對 C、D 的預測。但要理解任何一種實作，還得問三件事：

  1. 預測什麼？ 是分別預測幾個未來位置，還是建模整段候選的關係？到了推薦系統，token 甚至可能代表商品編碼或不同商品。
  2. 較遠的預測看見什麼？ 可以讓多個 head 都只依賴同一段前文，也可以讓後續模組接上中間 token 或前一步的表示。這會改變候選之間的一致性與計算方式。
  3. 額外訓練更新誰？ 若 loss 回傳到共享主模型，它可能改變 backbone 學到的表示；若凍結主模型、只訓練附加 heads，主要得到的是候選預測能力，不能直接宣稱主模型本身變強。

為什麼可能讓主模型學得更好？

若同一個表示除了要預測下一步，還要支援更遠的位置，它可能更需要保留對後續有用的資訊。例如程式中的分支選擇會影響後面一串 token；未來位置的 loss 可能讓相關線索得到更多直接監督。這是理解 MTP 可能有用的直覺，不是所有任務都會改善的保證。

不能因此直接說「模型學會規劃」。Gloeckle 等人的研究NotesMTP 預訓練：共享表示與獨立未來預測頭multi-token prediction...整理 Better & Faster Large Language Models via Multi-token Prediction 的研究定位、一手參考資料與後續補寫方向。同時討論這種機制假說，並用程式與其他任務測試；不同任務的收益並不一致。入口篇先保留這個證據邊界，架構、實驗與機制討論放到該篇細讀。Gloeckle et al., 2024, §3–5

也要記得前一節的梯度問題。MedusaNotesMedusa：多預測頭、候選樹與驗證解碼multi-token prediction...整理 Medusa: Simple LLM Inference Acceleration Framework with Multiple Decoding Heads 的研究定位、一手參考資料與後續補寫方向。同時討論凍結 backbone 只訓練 heads，以及共同調整主模型的路線；兩者可能改善的對象不同。Cai et al., 2024

所以「提升訓練效率」至少要拆成同資料量的表現、達到同表現所需的 token 數，以及 FLOPs／實際 GPU 時間。額外任務會增加成本；資料利用更好，不代表訓練時間自動更短。每篇方法筆記會分開核對這些指標，而不是把它們合成一個「更有效」。

多 token 候選，如何變成更快的生成？

現在回到推論：如果附加 heads 或模組能先提出 B C D，主模型就有機會一次評估這段候選，再依選定的規則接受其中可用的前綴。錯誤位置之後的候選不能直接沿用，需要修正並重新提出。Blockwise Parallel DecodingNotesBlockwise Parallel Decoding：猜測多步，再驗證最長前綴multi-token prediction...整理 Blockwise Parallel Decoding for Deep Autoregressive Models 的研究定位、一手參考資料與後續補寫方向。是理解「先猜一段、再驗證」的早期入口；減少的主要是主模型必須依序執行的輪次，總 FLOPs 未必減少。Stern et al., 2018

速度收益取決於候選有多便宜、每輪平均能接受多少 token，以及驗證、排程與硬體執行成本。候選越多，不一定越快。 具體的候選樹、接受規則與延遲數字，適合回到各方法筆記比較。

這裡也能看清 MTP 與 speculative decoding 的關係：前者描述多步預測的模型或訓練設計，後者描述「提出候選、驗證與接受」的解碼程序。Speculative decoding 可以使用獨立小模型作為 drafter，不必採用 MTP；MTP 也可以只在訓練中使用。Leviathan et al., 2023

收益的邊界，決定我們該怎麼比較

未來越遠，不確定性通常越大；增加 heads、loss 權重或預測距離，都需要在額外監督與任務難度之間取捨。候選之間的依賴也會影響接受率，並行預測並非唯一答案。Curriculum 研究甚至觀察到，主模型品質較好的配置不一定保留同樣的 self-speculative 加速收益。Aynetdinov & Akbik, 2025

因此，後續每篇筆記都沿著四個問題展開：預測什麼、每一步看見什麼、loss 更新哪些參數，以及推論如何使用與驗證。先對齊這些契約，再比較資料效率、表現與實際延遲，才能理解不同設計各自解決的問題。

  4. Leviathan, Y., Kalman, M., & Matias, Y. (2023). Fast Inference from Transformers via Speculative Decoding. ICML 2023, Proceedings of Machine Learning Research, 202.

    閱讀重點：接受、拒絕與修正採樣如何保留 target distribution；draft model 不必使用 MTP。

    閱讀重點：§2.2 的 sequential MTP、§4.5.1 訓練消融與 §5.4.3 推論用途；固定 v2 作細節來源。

  6. LLM-Core Xiaomi, et al. (2025). MiMo: Unlocking the Reasoning Potential of Language Model -- From Pretraining to Posttraining. Technical report; arXiv preprint.

    閱讀重點：§2.2 的聯合預訓練與新增 head 微調分階段；本文細節核對 v1，abstract 入口可查版本紀錄。

  7. Ankner, Z., et al. (2024). Hydra: Sequentially-Dependent Draft Heads for Medusa Decoding. COLM 2024.

Review Kit

Key Takeaways

  • NTP 對訓練序列各位置提供監督；訓練平行不代表生成已經沒有序列依賴。
  • MTP 增加未來位置的預測任務；是否改善主模型，要看 loss 是否更新 backbone 與實驗結果。
  • 資料效率、計算成本與 GPU 時間必須分開衡量；額外監督不是免費的。
  • 多 token 候選需要適當驗證；接受長度與總成本共同決定是否加速。
  • 保留 greedy 結果、保留採樣分布與維持評測品質，是不同保證。
  • 生成式推薦中的 token 可能代表商品編碼或商品本身；比較前先確認預測單位。
