1. 三類 token 各有責任

H-token 放跨場景的歷史行為，R-token 放較近的即時行為，T-token 放這次待評估目標的候選、情境及交叉特徵。不同業務可用自己的 tokenizer 轉換各自的 T 特徵，不必硬把所有場景欄位排成一模一樣的表格；長期與即時的使用者線索則可共用。美團技術文章 §3.1

共用 H：長期行為 ──┐
共用 R：即時行為 ──┼→ 共享骨幹 → 各業務的預測頭
場景 T：本次候選 ──┘

Mask 維持時間與候選邊界：T 只能看到當時已發生的 R；同請求的不同候選不能互看，否則一件商品的分數會受到同批其他候選影響。美團技術文章 §3.2

2. 為何同時有 Full 與 Target Attention？

讓全部長序列在每一層互相注意，成本高；但完全不讓歷史內部交互，也可能失去有效訊號。MTFM 因而穿插少數 Full Self-Attention 層與較多 Target Attention 層，把更多運算集中在要輸出分數的 T 側。這是計算分配策略，不是 T-token 從此不讀歷史。美團技術文章 §3.3

3. Target Scale-Up：一個候選為何要多個 token？

若候選側同時攜帶使用者、情境、商品及交叉特徵，把它們擠成一個向量可能過度壓縮。MTFM 的一個版本用 AutoSplit 將每個 target 的特徵映射成四個 token embeddings，並為不同 token 配置投影與 FFN，再做 token mixing。這不是「四個不同候選商品」，而是同一個待評估目標的四個表示位置。美團技術文章 §3.3.2

訓練時，MTFM 把同一使用者多個場景的曝光聚在一起，共用昂貴的長序列計算；部署時仍可按各業務取其相關部分。這是多場景精排統一，不等同於 OneTrans-V2NotesOneTrans-V2：一個使用者脈絡服務召回、粗排與精排推薦系統OneTrans-V2...從三級推薦流水線的重複歷史計算出發，理解 OneTrans-V2 的階段 token、生成式召回、SNT、跨階段快取與其限制。 所做的跨召回、粗排、精排三階段統一。美團技術文章 §3.4–4

Key Takeaways

  • H/R/T 分別承載歷史、即時行為與待評估 target；T 可保留場景差異。
  • Hybrid Target Attention 把更多計算放在候選側，仍讓候選讀取使用者脈絡。
  • 四個 target tokens 是同一候選的多個表示，不是四件商品。
  • MTFM 統一多業務精排；OneTrans-V2 統一推薦流水線的三個階段。
