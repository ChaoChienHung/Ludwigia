# Ludwigia World 地圖規劃藍圖規格書 (World Map Blueprint Specification)

本文件為 **Ludwigia World（數位花園虛擬空間）** 的全域地圖、分區佔地、道路網格、家具及植被擺放之單一真相來源（SSOT）。
後續任何新分區擴建、建築調整或家具增設，**皆須先在本文件完成座標與間距規劃，再同步落實至程式碼**，以杜絕空間擁擠、道路受阻與座標衝突。

## 6. 資料分塊與延遲載入擴展架構 (Data Scalability Architecture)

為解決 `characters.json` 隨著互動對話增加而變得臃腫（Bulky）的問題，制定以下分塊規範：

1. **核心名冊 (Core Manifest / `characters.json`)**:
   * 只保留每位 NPC 的基本規格：`id`, `name`, `role`, `gender`, `colors`, `initialPos`, `personality`, `avatarFallback`。
   * 單一檔案維持在 **15 KB 內**，首頁秒速下載。
2. **分區互動劇本 (Zone Interaction Chunks)**:
   * 依分區各自維護獨立的 JSON：
     * `data/interactions/dorm.json`（男十一舍專屬互動與床位對話）
     * `data/interactions/market.json`（宵夜街點餐與排隊互聊）
     * `data/interactions/basketball.json`（球場報隊與投籃對話）
     * `data/interactions/cafe.json`（咖啡廳品豆與寫程式對白）
   * 執行期依據玩家所在分區或接近特定家具時，按需非同步載入對應分區之台詞集。
3. **編譯驗證一致性**:
   * `tools/build_world_data.py` 同步支援全量編譯與分區分塊驗證，確保任何台詞引用之角色 ID 均合法存在於核心名冊中。

## 7. 渲染效能、GC 消除與互動體驗優化規格 (Performance, Zero-GC & Interaction Engineering)

為杜絕大規模等軸測世界在擴展過程中的卡頓（Jank / GC Pauses）並提升操作體驗，系統落實以下五大工程優化契約：

### 7.1 零 GC 靜態實體池 (Zero-GC Static Entity Management)
* **問題根源**: 原先每影格於 `collectWorldEntities()` 重新建構 180+ 個場景裝飾、牆體、家具與地圖物件，每秒產生超過 10,800 個短命物件與 Closure 函數分配，頻繁觸發瀏覽器 V8 Garbage Collection 微卡頓。
* **工程解法**:
  * 於 `LudwigiaWorld` 建構期一次性執行 `this.buildStaticWorldEntities()`，將所有靜態景物實例化為 `this.staticEntities` 陣列。
  * 預先計算並快取各實體幾何中心（`midX = (xMin + xMax) / 2`, `midY = (yMin + yMax) / 2`）與高度分層（`z`）。
  * 繪製閉包統一藉由 `this.ox` / `this.oy` 與日夜調色盤 Getter（`this.wallL`, `this.wallR`, `this.wallT`）動態求值，物件本體永不銷毀重新分配。
  * 每影格僅對動態角色（`this.charManager.characters`）進行輕量封裝並與靜態實體陣列合併，GC 負擔徹底歸零。

### 7.2 雙層視口幾何剔除 (Two-Tier Viewport Bounding-Box Culling)
* **地磚層剔除**: `drawTerrain()` 藉由相機原點、當前縮放比率與畫面視口（擴充 `margin = 140 / zoom`），在每格地磚渲染前以 `isoToScreen` 幾何檢驗，跳過 $80\%$ 以上的畫面外地磚繪製與 Path 運算。
* **實體層剔除**: 在進行等軸測深度拓撲排序（`sortIsometricEntities`）之前，預先過濾出視口內可見實體（`visibleEntities`），將排序複雜度由全圖 $O(N \log N)$ 陡降至可見集合 $O(K \log K)$（$K \ll N$）。

### 7.3 時間切片尋路佇列 (Time-Sliced Pathfinding Queue)
* **平滑分散 A* 負載**:
  * 多位 NPC（家人、同學、AI 夥伴、貓咪）同時結束徘徊時，若在同一個影格同時執行 A* 尋路會引發 CPU 計算尖峰與瞬間掉幀。
  * 引入 `this.pathQueue = []` 時間切片佇列，NPC 欲移動時透過 `this.requestNpcPath(char, targetX, targetY)` 入隊。
  * 於 `update(dt)` 每影格最多出隊並計算 1 位 NPC 之尋路路徑，均勻分散計算開銷。
* **玩家即時性硬保證**:
  * 玩家滑鼠點擊地圖與點擊 NPC 交談的尋路計算**維持 0ms 立即執行**，確保玩家操作毫無輸入延遲。

### 7.4 對話電影級運鏡聚焦 (Dialogue Cinematic Camera Pan & Lerp)
* **平滑中點插值 (Midpoint Framing)**:
  * 當玩家與 NPC 開啟交談時，呼叫 `setCinematicFocus(player, char)`，將相機目標坐標（`camTargetX, camTargetY`）設定為兩者幾何中點：
    $$\text{Target} = \left(\frac{X_{player} + X_{npc}}{2}, \frac{Y_{player} + Y_{npc}}{2}\right)$$
  * 同時疊加特寫焦距放大增益（`cinematicZoomBoost = +0.25`）。
* **指數平滑衰減 (Exponential Smoothing)**:
  * 相機與縮放皆採用指數平滑差值更新：
    $$\text{Pos}_{t} = \text{Pos}_{t-1} + (\text{Target} - \text{Pos}_{t-1}) \times (1 - e^{-8 \cdot dt})$$
  * 對話結束關閉時（`clearCinematicFocus`），鏡頭平滑滑回玩家自身軸心，無任何突兀跳變。

### 7.5 行動端觸控手勢原生支援 (Mobile Touch Gestures)
* **雙指縮放 (Pinch-to-Zoom)**:
  * 監聽 Canvas 上的多點觸控（`e.touches.length === 2`），依據兩點歐式距離變化動態縮放視野：
    $$\text{Scale} = \frac{\text{Dist}_{current}}{\text{Dist}_{initial}}$$
  * 縮放極限嚴格限制在 $[0.65, 2.2]$ 之間，保證畫面不破圖。
* **單指拖曳平移 (Drag-to-Pan)**:
  * 單指滑動超過 8px 時自動切換為地圖視野拖曳，更新 `panX` 與 `panY`。
* **輕點尋路判定 (Tap-to-Move)**:
  * 當觸控時間 $< 320\text{ms}$ 且移動位移 $< 8\text{px}$ 時，判定為短促點擊，自動派發 Click 事件以觸發路徑導航。

## 8. 場景互動事件系統規格 (Interaction Event System Specification)

為使 Ludwigia World 的角色社交互動具備生動的敘事節奏與空間沉浸感，所有 NPC 間的對話與群聚互動一律抽象收斂為**「事件」(Event)** 系統：

### 8.1 事件分類架構 (Event Taxonomy)
1. **地點強制事件 (Location-Bound Events / `type: "location_event"`)**:
   * **硬性空間約束**: 宣告 `requiredZone`（如 `dorm_211`, `house` / `ludwig_house`, `night_market`, `basketball_court`）。
   * **觸發前置條件**: 僅當參與名冊（`participants`）內的角色皆處於該分區時才具備觸發資格。
   * **空間動作聯動**: 可指定場景專屬狀態（如 `occupyBeds: true` 自動安排全員上床、特定座位入座）。
2. **自由漫遊事件 (Ambient Events / `type: "ambient_event"`)**:
   * **無固定地點限制**: 只要參與角色於開放校園（中央大道、噴泉廣場、綠廊）偶遇且彼此距離在對話半徑內（$\le 3.8 \sim 4.5$ 格），即隨機觸發日常碎念與打招呼。

### 8.2 異口同聲與合奏機制 (In-Unison Chorus Mechanics)
* **並發氣泡調度**:
  * 過去對話佇列僅支援逐句順序切換。為呈現家庭日常生活或多人集體反應，系統支援 `delay: 0` 零延遲標籤。
  * 當佇列解析到 `delay: 0` 時，執行期於同一影格立即出隊下一句台詞，促使多個角色同時彈出頭頂對白氣泡（`triggerSpeechBubble`）。
* **實裝案例**:
  * **家宅出門道別事件 (`family_departure_chorus_farewell`)**: 爸爸（趙武彥）說『那我先出去了喔。』後，趙健宏、妹妹（Luena）、媽媽（Yully）三人同時並發彈出氣泡異口同聲回應：『好，路上小心喔。』。

### 8.3 男十一舍 211 四人夜聊床位聯動 (Dorm Late-Night Bed Coordination)
* **床位精確映射**:
  * 事件標註 `occupyBeds: true` 時，角色管理器自動將四位室友綁定至專屬高架床鋪：
    * `billy` (方竣平) $\to$ `dorm_bed_billy`（東南床）
    * `clark` (吳宥謙) $\to$ `dorm_bed_clark`（東北床）
    * `jerry` (鍾昊哲) $\to$ `dorm_bed_kerry`（西南床）
    * `ludwig` (趙健宏) $\to$ `dorm_bed_happy`（西北床）
  * 調用 `useFurniture(c, spot)` 使角色自動平躺於上鋪床墊，並抑制呼嚕打呼氣泡，無縫切換為夜聊模式。
* **一人一句輪替對白 (`dorm_211_late_night_bed_chat`)**:
  * Clark、Jerry、Billy、趙健宏四人在寢室各床躺平，自然拋接日常話題（誰還沒睡、班上最漂亮的女生、黑皮戀情八卦、老開夜戰 Code 近況、早八微積分危機），最後互道晚安關燈入眠。
